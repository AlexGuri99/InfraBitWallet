# InfraBitWallet — Treasury Management

## 1. Overview

The treasury is a set of fee-collection addresses — one per chain — that receive the 0.35% swap fee. These addresses are controlled exclusively via hardware wallet (Ledger/Trezor). A multisig setup is planned for a future iteration.

**Security rules:**

- Treasury private keys are **never** on a server, in the repository, in any environment variable, or in any configuration file.
- Treasury addresses are **committed to config** (reviewed and signed off). They are not fetched from an API.
- Only **unsigned** withdrawal transactions are generated by scripts. Signing happens offline on the hardware wallet.

**Setup process:**

1. Generate each address using a hardware wallet.
2. Record the address and derivation path in a secure offline password manager (not in the repo).
3. Add the address (only the address string, not the path or seed) to config.
4. Verify the address on-device before committing.
5. Send a small test transaction to confirm receipt.

## 3. Fee Collection Mechanism

### STON.fi (TON)

- Referral fees accrue in the **DEX v2 Vault contract**.
- Withdrawal happens via the STON.fi SDK (`sdk.withdrawReferralFees` or similar).
- An admin script at `scripts/treasury-ton.ts` will:
  - Connect to the STON.fi API
  - Query accrued fees
  - Build an unsigned withdrawal transaction
  - Output the transaction for offline signing

### 0x Swap API (EVM)

- Fees are sent to the `swapFeeRecipient` address as part of each swap transaction.
- No withdrawal step is needed — fees arrive directly in the treasury address per swap.
- Accumulated fees can be viewed via any EVM block explorer.

### SunSwap (TRON) — TBD

- If manual collection: 0.35% sent alongside each swap as a parallel transfer. Treasury address receives directly per swap.

## 4. Claiming and Withdrawing

### Frequency

- Monthly review recommended, or when accrued fees exceed a threshold (e.g., $1000 equivalent).
- Withdrawal is always at the operator's discretion.

### Process

1. **Monitor:** Check fee accrual via:
   - STON.fi DEX REST statistics (vault accruals)
   - EVM block explorer (Etherscan for swapFeeRecipient)
   - TRON block explorer (Trongrid for fee address)
2. **Build withdrawal:** Run the appropriate admin script to build an unsigned withdrawal transaction.
3. **Sign offline:** Transfer the unsigned transaction (USB, QR) to the hardware wallet device. Sign.
4. **Broadcast:** Submit the signed transaction from a trusted environment.
5. **Verify:** Confirm the withdrawal reached the destination address.

## 5. Admin Scripts

Located in `scripts/`:

| Script                     | Purpose                                          | Notes                                             |
| -------------------------- | ------------------------------------------------ | ------------------------------------------------- |
| `scripts/treasury-ton.ts`  | Build unsigned STON.fi vault withdrawal          | Never signs                                       |
| `scripts/treasury-evm.ts`  | Build unsigned ETH/ERC-20 transfer from treasury | For moving accrued fees to a consolidation wallet |
| `scripts/treasury-tron.ts` | Build unsigned TRX/TRC-20 transfer from treasury | For TRON fee consolidation                        |

Each script:

- Reads treasury address from config (not from environment variables)
- Connects to the appropriate RPC or API
- Queries balances or accrued fees
- Builds an unsigned transaction
- Outputs the transaction hex to stdout
- **Never** requests or stores a private key

## 7. Security Considerations

- **Key compromise:** If a treasury address is compromised, swap fee recipients can be changed via a signed config update. Lost funds are limited to the accrued balance.
- **Replay attacks:** Each script includes chain-specific replay protection (chain ID, nonce).
- **Hardware wallet supply chain:** Purchase hardware wallets directly from the manufacturer.
- **Audit trail:** Every withdrawal should be documented with a tx hash, date, amount, and reason.
