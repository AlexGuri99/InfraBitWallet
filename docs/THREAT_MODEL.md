# InfraBitWallet — Threat Model (STRIDE)

## Scope

- **App:** Telegram Mini App (React, client-side crypto)
- **API:** Stateless Vercel endpoints (keyless, validates initData, proxies RPC/API keys)
- **Data:** BIP-39 24-word seed phrase, private keys, vault ciphertext, Telegram user data
- **Assets at risk:** Cryptocurrency funds, seed phrase, private keys, user privacy

## Vault implementation notes (Stage A/B/C)

- **Device secret.** A 32-byte value in Telegram SecureStorage is mixed into the key-wrap HKDF. A
  copied seal cannot be opened with the passcode alone. If SecureStorage is cleared while the seal
  needs it, the seal is unopenable (`device_secret_missing`) and the only recovery is re-importing
  the phrase after a wipe. This is documented in `docs/VAULT_DESIGN.md` and tested.
- **Session API.** `getPublicInfo`, `signDigest`, `reauthenticate`, `revealMnemonic`, `lock` — an
  allowlisted set of functions with no key bytes on any returned object. Signing is blind at this
  layer until adapters supply a `SigningRequest` with a payload-derived summary.
- **Rate limiting.** Persisted `nextAllowedAt`; only wrong passcodes count; `rate_limited` carries
  `retryAfterMs` and never runs Argon2. Wipe threshold is disabled by default.
- **Passcode policy (temporary).** 4-digit PIN with weak-PIN rejection. This is a deliberate
  pre-mainnet relaxation with the offline-brute-force consequence described in T11.
- **Exports.** `packages/crypto-vault/src/index.ts` is allowlist-tested so a new export that could
  return a seed, private key or vault key fails CI until reviewed.

## Security Assumptions

- User's Telegram account + device OS are trustworthy (we cannot defend against a rooted device with a keylogger).
- Telegram's WebView doesn't leak `initData` to third parties.
- OS Keychain/Keystore provides genuine hardware-backed encryption (iOS/Android).
- Device biometrics are not trivially bypassed.
- Provider APIs (STON.fi, 0x, Tonstakers, SunSwap) are honest and available.
- User backs up their 24-word seed phrase offline.

## Recommended Outside Scope for v1 Audit

- Smart contract security (TON V5R1, STON.fi, Tonstakers, SunSwap, 0x contracts) — these are assumed secure as established protocols.
- OS/Telegram security (WebView sandbox, Keychain, biometrics).
- Network-level attacks (ISP, DNS hijacking) — mitigated by HTTPS + SRI.
